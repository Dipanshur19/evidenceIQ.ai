## 📌 Demo Setup Checklist (Before Recording)
1. **Ollama running locally:** `ollama run qwen2.5:1.5b` (or let the fallback engine run).
2. **Launch React App:**
   ```bash
   cd evidenceiq-web/apps/api && node src/index.js
   cd evidenceiq-web/apps/web && npx vite --port 3000
   ```
3. **Open Browser:** Navigate to `http://localhost:3000` (or `http://localhost:8501` for Streamlit).
4. **Clean Screen:** Close unnecessary tabs, hide bookmarks bar, set browser zoom to 100%.

Rather than relying on arbitrary percentage triggers, our engine runs a 21-day rolling Gaussian baseline with day-of-week seasonality adjustments and a Dual Materiality Gate: an anomaly is only flagged if it exceeds $1.96\sigma$ AND represents at least ₹5 Lakh of real revenue-at-stake.*

### Segment 3: The 3D Business Evidence Graph & Causal Scoring (1:30 – 2:30)
- **Screen Action:** Navigate to **Investigation Page** (`/investigate` or `/investigation`). Rotate and interact with the **3D Evidence Graph**. Click on nodes.
- **Camera/Audio Voiceover:**
  > *"This is our **3D Business Evidence Graph**. Traditional AI hallucinates because it has no causal structure. EvidenceIQ.ai models business reality as a directed graph.*
  > 
  > *The central red node is our revenue disruption. Connected to it via directed `PRECEDES` edges are system change log events. Connected via `CORROBORATES` edges are real-time support ticket clusters.*
  > 
  > *Our engine evaluates hypotheses using a 6-factor deterministic scoring formula. It checks:*
  > 1. *Temporal Precedence: Did Mobile App Release v5.4 happen BEFORE the drop? Yes, exactly 4.2 hours prior.*
  > 2. *Unstructured Corroboration: Did support tickets spike? Yes, 14 tickets arrived with error 502 and payment failure keywords.*
  > 3. *Counterfactual Control: Did peer regions drop? No, South and West India held steady, proving the drop was isolated to the v5.4 mobile deployment.*
  >
